How to Refer to Files and Code

  • In IDE chat (VS Code / Visual Studio extensions), use Markdown links with paths relative to the workspace root:
    • A file: .github/copilot-instructions.md
    • A specific line: .claude/skills/whats-new-newsletter/SKILL.md#L42
    • A line range: TheWolfDen/Program.cs#L10-L25
    • A folder: .claude/skills/
  • In commit messages, pull requests, and code comments, use the file_path:line_number convention, for example TheWolfDen/Program.cs:42. Most tools render it as a jump link.

Attach context deliberately. In Copilot, use #file or selection references. In Claude Code, highlight the code to include it as context. Pointing the assistant to the right file is better than pasting a wall of code.

This is also how Skills and documentation cross-link. For example, a standards file can link directly to frontend-ui-conventions/SKILL.md for popover rules instead of repeating those rules.

如何引用文件和代码

  • 在 IDE 聊天窗口（VS Code / Visual Studio 扩展）中，使用 Markdown 链接，路径相对于工作区根目录：
    • 文件：.github/copilot-instructions.md
    • 指定行：.claude/skills/whats-new-newsletter/SKILL.md#L42
    • 行范围：TheWolfDen/Program.cs#L10-L25
    • 文件夹：.claude/skills/
  • 在提交说明、Pull Request 和代码注释中，使用 file_path:line_number 格式，例如 TheWolfDen/Program.cs:42。大多数工具会将其显示为可跳转链接。

有意识地提供上下文。在 Copilot 中使用 #file 或选区引用；在 Claude Code 中，选中代码即可将其作为上下文。准确指出相关文件，通常比粘贴大段代码更有效。

Skills 和文档之间也可以通过这种方式交叉引用。例如，标准规范文件可以直接链接到 frontend-ui-conventions/SKILL.md 中的弹出层规则，而不必重复描述这些规则。

Risks to Be Aware Of

AI-native tooling introduces a larger attack surface and new ways to make costly mistakes. Treat these risks as first-class concerns.

Hooks (Claude Code)

Hooks allow Claude Code to run arbitrary shell commands automatically in response to events (a tool call, prompt submission, or session end). This repository uses them for benign purposes: logging Skill usage and document reads, reporting usage, and producing session summaries through reviewed PowerShell scripts.

That same capability creates risk: a hook can run without asking for your approval each time.

  • Review every hook before it is merged, just like any other code. Keep scripts in .claude/hooks/ so changes can be reviewed in diffs.
  • Be suspicious of hooks introduced through settings.local.json or a cloned repository you did not create. A malicious hook is simply code that runs automatically on your machine.
  • Copilot does not currently have an equivalent automatic shell-execution hook mechanism; this is a Claude-Code-specific consideration.

Editor extensions

  • Disable automatic updates for extensions you do not strongly trust. An auto-updating extension can push compromised or hijacked code onto your machine without a review step. Pin versions and update deliberately.
  • Prefer first-party or well-established extensions, and audit the permissions an extension requests.

Dependencies and the software supply chain

This is a major concern, and AI assistants can amplify it because they readily suggest packages to solve problems.

  • Open-source packages (npm, NuGet, PyPI, etc.) are targets for compromise. Attackers may take over a maintainer account or use a typosquatted package name to publish a malicious version. More dependencies mean greater exposure.
  • Reduce dependency scope. Avoid adding a package for something you can implement in a few lines. When an assistant says “just add library X,” assess whether the dependency is worth the supply-chain risk—not merely how much code it saves.
  • Pin and review dependencies. Lock versions, carefully review project-file changes (such as .csproj and package.json) in pull requests, and prefer well-maintained, widely used packages over niche ones.
  • Internal data-silo NuGet packages (ProductDevDb, QualityOpsDb, DwsGlobalEnums, etc.) are under our control and have a different risk profile from public registries, but their versions should still be pinned and every update reviewed.
Key principle: Anything that runs automatically—hooks, auto-updating extensions, or transitive dependencies—is something a person did not approve at the moment it ran. Keep that set small, reviewed, and version-pinned.

需要注意的风险

AI 原生工具扩大了攻击面，也带来了新的失误方式。应当把这些风险作为重要事项认真管理。

Hooks（Claude Code）

Hooks 可以让 Claude Code 在特定事件发生时（例如调用工具、提交提示词或会话结束）自动运行任意 Shell 命令。本仓库将它们用于良性用途：通过经过审查的 PowerShell 脚本记录 Skill 使用情况和文档读取情况、报告使用统计，以及生成会话摘要。

但同一种能力也带来了风险：Hook 每次运行时都不一定会再次征求你的许可。

  • 每个 Hook 在合并前都必须审查，就像审查其他代码一样。将脚本保存在 .claude/hooks/ 中，以便通过代码差异进行检查。
  • 对于通过 settings.local.json 或你并未创建的克隆仓库引入的 Hook，要保持警惕。恶意 Hook 本质上就是一段会在你的机器上自动运行的代码。
  • Copilot 目前没有等同的自动运行 Shell 命令 Hook 机制；这是 Claude Code 特有的注意事项。

编辑器扩展

  • 对于不够信任的扩展，关闭自动更新。自动更新的扩展可能在未经你审查的情况下，将被入侵或劫持的代码推送到你的机器上。应固定版本，并有意识地更新。
  • 优先选择官方或信誉良好的扩展，并检查扩展申请的权限。

依赖项与软件供应链

这是一个重要风险。AI 助手经常会主动推荐软件包来解决问题，因此可能进一步放大这一风险。

  • 开源软件包（npm、NuGet、PyPI 等）是攻击者的重点目标。攻击者可能接管维护者账号，或利用拼写相似的恶意包名发布恶意版本。依赖越多，暴露面越大。
  • 尽量缩小依赖范围。几行代码就能实现的功能，不要轻易引入一个新包。当助手建议“直接添加库 X”时，应评估该依赖带来的供应链风险是否值得，而不只是看它能减少多少代码。
  • 固定并审查依赖版本。锁定版本；在 Pull Request 中仔细审查项目文件（例如 .csproj 和 package.json）的变更；优先选择维护良好、使用广泛的软件包，而不是小众包。
  • 内部数据隔离 NuGet 包（ProductDevDb、QualityOpsDb、DwsGlobalEnums 等）由我们控制，其风险情况不同于公共软件包仓库；但仍应固定版本，并在每次升级时进行审查。
核心原则：任何自动运行的内容——Hook、自动更新的扩展，或传递依赖——都意味着它运行时没有经过人工即时批准。应尽量减少这类内容，并确保它们经过审查且版本固定。

Additional safety reminders

  • Limit npm and NuGet packages to the bare minimum. Every public package adds an attack vector. Attackers target these repositories, and malicious code can make its way onto your work or personal machine.
  • The same applies to browser, VS Code, and other tool extensions. Use trusted names and limit exposure. Do not enable auto-update for VS Code extensions unless the source is highly trusted.
  • An extension can be compromised, allowing a subtle malicious update to be pushed automatically.
  • Open-source software may become increasingly risky to consume. This could significantly change our development environment. The positive side is that as AI-assisted development skills improve and models become more capable, we may be able to write more of the small tools we need ourselves, reducing our attack surface.

其他安全提醒

  • 将 npm 和 NuGet 软件包的使用量限制在最低必要范围。每个公共软件包都会增加一个攻击入口。攻击者正在针对这些软件包仓库发动攻击，恶意代码可能因此进入你的工作电脑或个人电脑。
  • 浏览器扩展、VS Code 扩展以及其他工具扩展也存在同样的问题。只使用可信度高的扩展，并尽量减少暴露面。除非扩展来源高度可信，否则不要为 VS Code 扩展启用自动更新。
  • 扩展可能遭到入侵，攻击者随后便可能自动推送不易察觉的恶意更新。
  • 使用开源软件的风险可能会越来越高，这可能显著改变我们的开发环境。积极的一面是，随着 AI 辅助开发能力不断提高、模型越来越强，我们可能可以自行编写更多日常所需的小工具，从而减少攻击面。
